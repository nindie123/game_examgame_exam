## 发现（按严重度）

### 1. 高（已修复，待 Unity 验证，2026-11-02）| 控制器先推进 `_board` 再交给视图，动画「前帧」取到后帧

- 位置：[BoardController.cs:171-174](../../Assets/Scripts/Presentation/BoardController.cs#L171-L174)（非下落）、[BoardController.cs:164-165](../../Assets/Scripts/Presentation/BoardController.cs#L164-L165)（下落）；[BoardView.Playback.cs:167](../../Assets/Scripts/Presentation/BoardView.Playback.cs#L167)（`var before = _board;`）、[BoardView.Playback.cs:96](../../Assets/Scripts/Presentation/BoardView.Playback.cs#L96)（`PlayFalls` 用 `_board` 建起始轨迹）。
- 说明：`PlayStep` 的正确语义是「以视图当前帧为前帧、以 `step.Board` 为后帧」做过渡：前帧对象经 `old` 表映射到其当前 Transform，后帧中新增对象才在目标位创建、消失对象才做移除动画。该语义要求 `before == 前一步的棋盘` 且 `_pieceTransforms` 仍是前一步的画面布局。但控制器在 `yield return view.PlayStep(step)` **之前**执行 `_board=step.Board`，于是 `before=_board` 取到的是 `step.Board`（后帧）。以交换步为例：`old[B]=trA`、`old[A]=trB`（对象↔Transform 错位），后帧对象全部命中 `old`，位移为零、无移除，最终 `_pieceTransforms` 与交换前完全相同——**有效交换不会显示棋子交换**。消除、下落同理（`PlayFalls` 读到的 `_board` 已是下落终点棋盘）。该缺陷自 `da3dbca` 即存在，本轮未改；因文档明确「未在 Unity 中执行、正常动画与无动画对比尚未执行」，一直未被暴露。
- 更正：上一版审查曾把「PlayStep 以滞后的 `_board` 作前帧、映射正确」列为「已核对无问题」，本轮复核后判定为错误，予以更正。
- 建议（已按此实施）：先取消耗步骤（`yield return view.PlayStep/PlayFalls(...)`），再推进 `_board=step.Board`；`NoAnimation` 分支改为显式 `RenderSnapshot(step.Board)` / `RenderSnapshot(falls[last].Board)`。已于 2026-11-02 修改 `BoardController` 非下落与下落两处，规则层与测试未动；仍需在 Unity Play Mode 逐步骤核验交换、消除、下落、收集动画。

### 2. 中 | 道具步骤类型经 `ElementType.ToString()` → `Enum.Parse` 字符串桥梁派生，控制器仍混用字符串分支

- 位置：[SimulationStep.cs:20,36](../../Assets/Scripts/Rules/Simulation/SimulationStep.cs#L20-L36)、[TurnSolver.cs:32](../../Assets/Scripts/Rules/Simulation/TurnSolver.cs#L32)、[BoardController.cs:146,157,175](../../Assets/Scripts/Presentation/BoardController.cs#L146-L175)
- 说明：`SimulationStep.Kind` 现为 `Type.ToString()` 只读派生，`StepKind` 枚举成为单一真源（较纯字符串版已实质改善）；但 `PropEffects.Execute` 以 `prop.Type.ToString()` 构造 Kind，与 `ElementType` 枚举成员名形成两枚枚举的隐式耦合——任一侧改名即 `Enum.Parse` 抛异常（被 TurnSolver 包装成 Error 步骤），无编译期保护。控制器仍以 `step.Kind=="Fall"/"Refill"/"Victory"` 字符串分支，与 `step.Type==StepKind.X` 枚举分支并存，风格不一。
- 建议：`SimulationStep` 构造直接接收 `StepKind`（由规则层用 `switch` 显式映射 `ElementType→StepKind`），控制器全部改用 `step.Type` 比较。

## 已核对且未发现问题的方面

- 快照不可变：`BoardState` 构造 clone + 每次 `new BoardState(w,h,a)` 复制可变数组，`yield` 出的步骤不被后续覆盖。
- 对象编号唯一：`SimulationContext` 从现有最大 id+1 起、`Spawn`/`MatchGroups` 共用；`SimulationStep` 对非 Error 步骤构造时 `BoardData.Validate`。
- 结算契约：`ObjectChange`（含创建 `From=-1`/移除 `To=-1`）与权威棋盘一致；`StepId` 全局递增；`TargetDelta` 与 `CountBackpacks` 差值一致（A11 测试覆盖）。
- 会话/步骤隔离：`SessionGate` 拒绝旧会话/旧步骤/乱序提交（`Commit` 对 `step<=Step` 抛异常），重开 `StopAllCoroutines` + 重建视图与上下文。
- 回放：Header 含种子/半径/上限/初始摘要，`Digest` 含随机状态，`FirstDifference` 首分歧定位，导出可重放。
- 螺旋桨远端表现：读规则实际 `HitCells`，唯一 `曼哈顿距离>1` 的背包即远端目标，不再在视图重复选目标。
- 视觉随机与玩法随机隔离：`SparkBurst` 用固定角度，不消耗 `SimulationContext` 随机流。
