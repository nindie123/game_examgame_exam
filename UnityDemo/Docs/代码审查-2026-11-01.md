## 总体结论

- **规则层（纯 C#）正确性良好**，与计划书二、三章对齐，未发现功能性缺陷（与既有 70 项断言通过一致）。关键点均核对无误：
  - 快照不可变：`BoardState` 构造 clone；Simulation 层每次 `new BoardState(w,h,a)` 也 clone 可变数组 `a`，`yield` 出的 `SimulationStep` 不会被后续原地修改污染。
  - 对象编号唯一：`SimulationContext` 从现有最大 id+1 起分配，`Spawn` 与 `MatchGroups` 共用 `NextId++`。
  - 匹配分组：重叠/传递合并；优先级炸弹＞火箭＞螺旋桨；交换落点优先生成、连锁生成取最下最左；原棋子全部统一清除后再放置道具。
  - 道具队列：`ObjectId` 去重 + FIFO；火箭整行/列、炸弹裁切 5×5、螺旋桨先局部后远端（从上到下、同行从右到左）。
  - 下落：垂直优先、斜向仅当正下方被占、双背包对角缝阻挡、仅顶部补充、封闭空区保持空；均有固定局面测试。
  - 异常保护：100 轮连锁上限、死局最多 100 次重排，失败抛异常由控制器捕获并提示重开。
  - 表现与规则分离：动画按对象编号复用画面对象、回调不写 `BoardState`；视觉随机（SparkBurst 固定角度）不消耗玩法随机数。
- 以下为若干**中低风险**的代码质量与架构问题，均不阻塞 Unity Play Mode 核验。

## 发现（按严重度）

### 1. 中 | Simulation 层大量无注释魔法数与压缩写法

- 位置：[TurnSolver.cs:8-80](../../Assets/Scripts/Rules/Simulation/TurnSolver.cs#L8-L80)、[MatchGroups.cs:8-72](../../Assets/Scripts/Rules/Simulation/MatchGroups.cs#L8-L72)、[GravitySolver.cs:8-47](../../Assets/Scripts/Rules/Simulation/GravitySolver.cs#L8-L47)、[SimulationContext.cs:1-53](../../Assets/Scripts/Rules/Simulation/SimulationContext.cs#L1-L53)
- 说明：`Shape.Rank` 用裸 int 编码（0=三连、1=螺旋桨、2=火箭、3=炸弹，见 [MatchGroups.cs:26,29,38,66](../../Assets/Scripts/Rules/Simulation/MatchGroups.cs#L26)）；100 轮连锁上限（`for(int round=0;round<100;round++)`）、死局 100 次重排、xorshift 常量 `0x9e3779b9`、`Spawn` 用 `(PieceColor)(1+Next(ref RandomState,4))` 从数字推导颜色，均无注释解释规则依据。与原 `Rules/Board`、`Rules/Legality` 的注释密度形成明显反差，违反 CLAUDE.md §4「数值参数集中管理、注释解释规则原因」。
- 建议：`Rank` 提为枚举；100 轮/乱数常量集中命名并注明来源；`Spawn` 颜色映射注明枚举顺序约定。

### 2. 中 | 结算步骤用字符串类型，无步骤序号与会话编号

- 位置：[SimulationContext.cs:46-53](../../Assets/Scripts/Rules/Simulation/SimulationContext.cs#L46-L53)、[BoardController.cs:70-98](../../Assets/Scripts/Presentation/BoardController.cs#L70-L98)
- 说明：`SimulationStep.Kind` 是裸 string（"Swap"/"Match"/"Fall"/"Refill"/"Victory"/"Ready"/"Shuffle"/"Rocket"/"Bomb"/"Propeller"），控制器以 `step.Kind=="..."` 硬编码分支。计划书 §3.3/§3.4 要求 `ResolutionStep` 携带步骤序号与会话编号；当前会话隔离只落在 `BoardController`（`_session` + 停协程），步骤本身不承载会话编号。字符串协议在拼写错误时静默失效。
- 建议：`Kind` 提为枚举（或至少集中为常量）；如不引入步骤序号，在注释中显式声明该简化及会话隔离的承载位置。

### 3. 低 | 旧 T03 表现方法成为死代码

- 位置：[BoardView.cs:37-40](../..//Assets/Scripts/Presentation/BoardView.cs#L37-L40)、[BoardView.cs:461](../../Assets/Scripts/Presentation/BoardView.cs#L461)、[BoardView.cs:518](../../Assets/Scripts/Presentation/BoardView.cs#L518)、[BoardView.cs:534](../../Assets/Scripts/Presentation/BoardView.cs#L534)、[BoardView.cs:556](../../Assets/Scripts/Presentation/BoardView.cs#L556)
- 说明：`FinalizeSwap`、`RemoveOccupants`、`ApplyCommittedBoard`、`HideHint` 与常量 `SwapDuration`、`HintHoldSeconds`、`SpecialSwapHint`、`RoundCompleteHint` 已无调用方（grep 确认），被 Playback 流程取代；`AnimateSwap` 仍用于无效交换回退，但其调用处用字面量 `0.16f` 而非 `SwapDuration`（值为 0.18f），常量本身已与实现脱节。`SwapResolver`/`SwapResolverTests` 已由 `Docs/实现过程与验证记录-2026-10-31.md` 声明为「保留的旧阶段接口」，但这批 `BoardView` 方法未声明保留，属被替代的重复实现，违反 §5。
- 建议：删除或明确标注迁移；统一无效回退动画时长。

### 4. 低 | SimulationContext 的随机/游标状态为公开可变字段

- 位置：[SimulationContext.cs:8-28](../../Assets/Scripts/Rules/Simulation/SimulationContext.cs#L8-L28)、[BoardController.cs:41-43](../../Assets/Scripts/Presentation/BoardController.cs#L41-L43)
- 说明：`NextId`/`Cursor`/`RandomState`/`ShuffleState` 全为 public 字段，`Spawn`/`Shuffle` 用 `ref` 原地推进。确定性靠调用方约定（`ChooseMove` 每次复制一份再逐字段覆写），忘记复制即污染本局随机流。语义隐晦、误用面大。
- 建议：收敛为方法（推进并返回新值）或至少封装只读游标；`ChooseMove` 的复制+覆写抽成 `ctx.Fork()` 之类的显式接口。

### 5. 低 | 控制器用屏幕像素写死按钮遮挡判定

- 位置：[BoardController.cs:27](../../Assets/Scripts/Presentation/BoardController.cs#L27)
- 说明：`mouse.position.ReadValue().y < 65` 与 `OnGUI` 按钮布局硬耦合；布局/字号调整需同步该魔法数，且 65px 无命名无注释。
- 建议：抽为与按钮布局共用的大上限常量，或改用事件系统挡 UI 点击。

### 6. 信息 | 规则层用一维数组与索引运算直写棋盘

- 位置：[BoardData.Copy](../../Assets/Scripts/Rules/Simulation/SimulationContext.cs#L32-L36) 及 Simulation 各模块内 `k/w`、`k%w`、`a[k±w]`（如 [MatchGroups.cs:19-28](../../Assets/Scripts/Rules/Simulation/MatchGroups.cs#L19-L28)）
- 说明：计划书 §3.6 允许一维数组存储，该写法不违反约定；但 Simulation 模块绕开 `BoardState`/`BoardPosition` 类型 API，直写可变副本，仅在 `SimulationStep` 构造时用 `BoardData.Validate` 做一次重复 id 检查。属可读性/易错性风险，非当前 bug。
- 建议：如需长期演进，可用带边界检查的 `Grid<T>` 小封装提升安全性；当前 Demo 规模可接受。
