## 发现（按严重度）

### 1. 低 | 控制器只允许普通棋子互swap，道具触发交换在 UI 上不可达

- 位置：[BoardController.cs:65-70](../../Assets/Scripts/Presentation/BoardController.cs#L65-L70)
- 说明：只在 `clicked.Type == NormalPiece` 时继续，`SwapEvaluator` 的 `PropTrigger` 分支（[SwapEvaluator.cs:39-42](../../Assets/Scripts/Rules/Legality/SwapEvaluator.cs#L39-L42)）永远无法由玩家触发。演示布局无道具，当前无实际影响；属「规则层支持 / 表现层不支持」的隐性分歧，接入道具前需对齐。
- 结论：待道具接入时处理，非 T02 阻塞项。

### 2. 低 | 相邻判定在控制器与规则层重复实现

- 位置：[BoardController.cs:158-161](../../Assets/Scripts/Presentation/BoardController.cs#L158-L161) 与 [SwapEvaluator.cs:96-101](../../Assets/Scripts/Rules/Legality/SwapEvaluator.cs#L96-L101)
- 说明：两处 `IsAdjacent` 完全相同，而 [BoardController.cs:113-114](../../Assets/Scripts/Presentation/BoardController.cs#L113-L114) 注释声称「控制器不重复任何规则逻辑」。相邻定义变更需两处同步。
- 建议：控制器只做「改选 vs 请求交换」的早期分流，或明确注释这是表现层提前退出门。

### 3. 低 | `BoardState.WithSwap` 未防御 `first == second`

- 位置：[BoardState.cs:85-104](../../Assets/Scripts/Rules/Board/BoardState.cs#L85-L104)
- 说明：只校验两个坐标在界内，不校验两者不同。当前所有调用方（`SwapEvaluator` 先做相邻检查）都保证不同位，无实际 bug；但作为公开 API，建议加防御或文档注明「要求两个位置不同」。

### 4. 低 | 顶部背包计数仅在 Render 时读取一次

- 位置：[BoardView.cs:301-325](../../Assets/Scripts/Presentation/BoardView.cs#L301-L325)
- 说明：用 `_board.CountBackpacks()` 生成计数后不再刷新，消除/补充落地后 UI 不会自动更新。T02 内无害，属已知前置限制，需在消除结算中作为待办闭环。

### 5. 低 | `ScreenToWorld` 无主相机时返回 `Vector3.zero`

- 位置：[BoardController.cs:146-156](../../Assets/Scripts/Presentation/BoardController.cs#L146-L156)
- 说明：`Camera.main == null` 时返回零向量，再靠下游 `_board == null` 保护兜底。当前 `Render` 已先要求主相机，实际不可达；建议返回有含义的哨兵值或提前 return。

## 已核对且未发现问题的方面

- 同一配置重复得到相同棋盘（确定性）。
