## 总体结论

- 「先让视图消费步骤、再推进 `_board`」的排序修复**方向正确**：非下落（`PlayStep`）与下落（`PlayFalls`）两处均已按 `Docs/代码审查-2026-11-01.md` 发现 1 的建议实施，`NoAnimation` 分支也显式改为 `RenderSnapshot(step.Board)` / `RenderSnapshot(falls[last].Board)`，逻辑自洽。
- 但本次改动暴露了以下风险：两处动画调用仍在 try/catch 之外（既有）、`PlayFalls` 缺少与 `PlayStep` 一致的空判（既有）、权威 `_board` 双副本错位（本次引入），以及四处视觉参数与一个 `preloadedAssets` 条目的无关改动（本次引入，未记录、未验收）。

## 发现（按严重度）

### 1. 高（既有，非本轮回归）｜ 动画抛异常导致输入永久软锁

- 位置：[BoardController.cs:164](../../Assets/Scripts/Presentation/BoardController.cs#L164)、[BoardController.cs:173](../../Assets/Scripts/Presentation/BoardController.cs#L173)、[BoardController.cs:122](../../Assets/Scripts/Presentation/BoardController.cs#L122)（`_busy=true`）、[BoardController.cs:184](../../Assets/Scripts/Presentation/BoardController.cs#L184)（`_busy=false`）
- 说明：`yield return _view.PlayStep(step)` / `_view.PlayFalls(falls)` 不在任何 try/catch 内；`_busy` 只在 `Play` 末尾、非法交换（[BoardController.cs:126](../../Assets/Scripts/Presentation/BoardController.cs#L126)）或胜利（[BoardController.cs:176](../../Assets/Scripts/Presentation/BoardController.cs#L176)）处清空。若视图动画中途抛异常（如 `_pieceTransforms` 与 `_board` 失配、贴图引用被销毁），异常直接传出 `Play`，无人清空 `_busy`，后续输入全部被锁死直到手动重开。
- 判定：该 try/catch 结构在本轮 diff 之前即如此（视图调用从不包 try/catch），属**既有潜在缺陷**，非本次排序修复引入的回归，但建议补上防护。
- 建议：将两处 `yield return _view.PlayStep/PlayFalls(...)` 包入 try/catch，异常时走 `EnterError` 并清 `_busy`。

### 2. 高（既有）｜ `PlayFalls` 缺少空值保护，存在 NRE 路径

- 位置：[BoardView.Playback.cs:100-101](../../Assets/Scripts/Presentation/BoardView.Playback.cs#L100-L101)
- 说明：`var tr = _pieceTransforms[p.Row, p.Column]; … new Motion { Transform = tr, Scale = tr.localScale }` 直接解引用 `tr.localScale`，无空判。对比同文件 [`PlayStep`](../../Assets/Scripts/Presentation/BoardView.Playback.cs#L174) 使用 `cell.IsOccupied && tr != null` 做了保护。一旦 `_pieceTransforms` 与 `_board` 出现视图/数据不同步（正是发现 1 修复针对的那类问题），此处会抛 NullReferenceException，并连锁触发发现 1 的软锁。
- 建议：在 [BoardView.Playback.cs:100](../../Assets/Scripts/Presentation/BoardView.Playback.cs#L100) 补 `if (!cell.IsOccupied || tr == null) continue;`，与 `PlayStep` 对齐。

### 3. 中（本轮引入）｜ 权威 `_board` 双副本与一步错位

- 位置：[BoardController.cs:173-174](../../Assets/Scripts/Presentation/BoardController.cs#L173-L174)、[BoardView.Playback.cs:218](../../Assets/Scripts/Presentation/BoardView.Playback.cs#L218)、[BoardView.Playback.cs:139](../../Assets/Scripts/Presentation/BoardView.Playback.cs#L139)
- 说明：`BoardController._board` 与 `BoardView._board` 两份副本需在「动画中途刻意错开一步」的前提下保持一致：视图在 `PlayStep`/`PlayFalls` 内部推进自己的 `_board`，控制器随后才推进自己的 `_board`。任何在动画窗口期间读取控制器 `_board` 的代码都会拿到旧棋盘，且这份冗余让排序修复极易被后续改动回退。
- 建议：后续收敛为单一权威持有者（例如视图只持有「前帧快照」，控制器 `_board` 保持唯一权威），消除漂移风险。
